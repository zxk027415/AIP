# 交付前自审（Self-Review Before Delivery）

代码改完、构建通过之后，**不能直接说"完成了"**。必须先做一轮自审，确认没有遗漏，再交付。

## 自审流程

1. **重新读一遍改过的文件**，不是凭记忆。
2. **对照设计规约/需求逐项检查**：
   - 规约里定义的每一条规则是否在代码中体现。
   - 有没有遗漏的状态（空态、加载态、错误态、禁用态）。
   - 有没有未使用的 import、变量、死代码。
3. **跑构建/类型检查**：确认 0 error。Warning 是否全是既有的。
4. **检查是否有副作用**：
   - 改了公共组件（如 MainLayout）是否影响其他页面。
   - 新 import 的模块是否存在。
   - 路由变化是否会导致 404。
5. **写交付说明**：
   - 改了哪些文件、每个文件改了什么。
   - 验证了什么（构建、类型检查、截图）。
   - **没验证什么**（如未启动 dev server 手动查看）。
   - 风险和后续建议。

## 原则

- 自审不是走过场，是**替用户省一轮 review**。
- 发现问题就地修，不要留着说"这个后面再改"。
- 交付时的措辞是"已自审，以下是结果"，而不是"应该没问题"。
