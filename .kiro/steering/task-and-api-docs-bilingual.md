# 任务说明与 API 文档写法（通用）

在撰写**任务交接、设计说明、接口说明**（尤其是：**双版本对比回测、候选准入、人工 Promote、生产/基线登记**）时，遵守下列约定。内容**不绑定**某一仓库目录或技术栈名称；实现可以是任意语言与存储。

## 1. 英文字段名必须带中文注解

- 首次出现的 **JSON 字段名、路径参数、查询参数、文件名** 采用格式：**`field_name` — 中文含义（必要时加一句用途）**。
- 表格中可在「字段」列写英文 key，在「说明」列写中文；或在同一单元格内 **`workflow_id`（工作流/模板唯一标识）**。
- 避免只贴英文 key 列表而不解释；避免假设读者熟悉内部缩写。

## 2. 登记类持久化（registry / 审计）要讲清四件事

说明任意「**登记文件**」或「**注册表**」时，至少交代：

1. **存什么**：例如「当前认定的生产基线对应哪一个模板 ID」。
2. **为什么单独存**：例如「与主业务库未打通前的约定真源」「供 UI 预填与跳转」。
3. **按什么维度分区**：例如按 **`slot`（槽位）** — 多环境/多产品线时分区键；默认槽位名可写 **`default`（默认槽）**。
4. **路径/介质**：写「由部署配置决定」或「相对配置目录的某某文件名」，**不写死**仅适用于某一克隆仓库的绝对路径。

## 3. REST 接口说明模板（可复制结构）

对 **GET「只读登记」** 类接口，写明：

- **用途**：谁在什么场景调用（UI 展示 / CLI / 另一服务预填）。
- **返回体**：对 **`slots`**（槽位字典）、**`workflow_id`（登记的模板 ID）**、**`updated_at`（最后更新时间）**、**`note`（备注）**、**`source_candidate_id`（来源候选 ID，便于审计）** 等逐项 **`英文 — 中文`**。

对 **PUT/PATCH「写入登记」** 类接口，写明：

- **语义**：覆盖指定槽位下的登记，是否全量替换该槽位对象。
- **请求体**：**`workflow_id` — 必填，要登记为真源的模板 ID**；**`slot` — 可选，槽位，默认 `default`**；**`note` — 可选，人类可读备注**。

## 4. Promote（晋升/采纳）与生产登记联动

说明 **Promote** 接口时，必须写清：

- **`candidate_id`（候选记录 ID）** — 路径或 body 中如何标识一条候选。
- **`set_as_production`（是否同步写入生产登记）** — 布尔；为真时，除更新候选状态外，还要把**哪一条模板 ID** 写入 registry（见下条）。
- **`production_slot`（写入生产登记时使用的槽位）** — 可选，默认与 PUT 登记接口的 `slot` 一致。
- **与 Challenger/Baseline 的语义**：若业务含义是「胜出方接替生产」，应明确写入 registry 的是 **`challenger_workflow_id`（实验/挑战者模板 ID）** 还是 **`baseline_workflow_id`（基线模板 ID）**；禁止让读者猜。

## 5. 审计日志（append-only log）

若存在 **`promotions_log`（晋升操作日志）** 或等价物，说明：

- **是否只追加**、**是否可篡改**（通常只追加）。
- **每条大致字段**：**`candidate_id`（候选 ID）**、**`challenger_workflow_id`（挑战者 ID）**、**`set_as_production`（是否改生产登记）**、**`production_slot`（槽位）**、时间戳等 —— 均附中文。

## 6. 多窗对比任务（异步）说明要点

若涉及 **compare / backtest-batch-async** 类任务，说明中应包含（仍用 **`英文 — 中文`**）：

- **`comparison_id`（比对任务 ID）** — 用于轮询状态。
- **`evaluation_contract`（评测量约）** — 与「被测模板内部结构」区分：固定的是**尺子**，不是**被测对象**。
- **`score_margin`（分差门槛）**、**`aggregate_method`（跨窗聚合方式，如 mean/median）**、**`min_windows_challenger_better`（最少优胜窗数）** 等准入条件。
- **`eligible_for_pool`（是否满足入池条件）** 与分项条件（如 **`meets_score_margin`（是否满足分差）**、**`meets_win_count`（是否满足优胜窗数）**）若分开返回，需分别注解。

## 7. 任务交接文档自检清单

- [ ] 所有关键 JSON 字段首次出现均有 **中文注解**。
- [ ] 登记文件 / registry 的 **用途、槽位、与主库关系** 已说明。
- [ ] GET/PUT 登记接口的 **调用方与副作用** 已区分（只读 vs 覆盖写）。
- [ ] Promote 的 **`set_as_production`** 为真时，**写入的到底是哪类 workflow_id** 已写死讲清。
- [ ] 审计日志文件名/用途已说明，且未与「业务主数据」混淆。
