## 1. 工作背景与目标

AIP 工业 AI 算法平台的基础算法库定义了 **769 个算子**（`functions.json`），但绝大多数只有元数据定义（名称、参数描述），没有后端执行代码——用户在工作流中拖拽这些算子后无法实际运行。

**本次目标**：
1. 分三批（P0/P1/P2）填充 **67 个通用算子**的真实后端实现
2. 在前端为**所有已实现算子**添加"可执行"视觉标记
3. 建立 **5 层分层测试体系**，确保算子的通用性、规范性和精度可验证
4. 用真实业务数据（负荷预测 + 光伏故障诊断）做**端到端精度对比**

## 4. 前端"可执行"徽标系统

### 4.1 架构

```
前端 FunctionLibraryPage
    │  useBackendReadyOperators() hook
    ▼
GET /api/functions/backend-status  ──►  OperatorRouter.list_operators()
    │                                        │
    │  返回 112 个已注册算子 ID              │
    ▼                                        ▼
readySet (Set<string>, 含别名映射)     前端卡片判断:
    │                                    readySet.has(fn.id)
    ▼                                        │
绿色 "可执行" Tag  |  灰色 "仅定义" Tag      筛选按钮: 全部/仅可执行/仅定义
```

### 4.2 前后端命名别名映射

前端目录用语义后缀（`arima_forecast`、`kmeans_cluster`），后端用规范名（`arima`、`kmeans`）。通过 `useBackendReadyOperators.ts` 内的 `FRONTEND_TO_BACKEND_ALIASES`（23 条映射）统一：

```typescript
const FRONTEND_TO_BACKEND_ALIASES = {
  arima_forecast: 'arima',
  prophet_forecast: 'prophet',
  pca_reduce: 'pca',
  kmeans_cluster: 'kmeans',
  // ...共 23 条
};
```

### 4.3 覆盖效果

- 后端注册 112 个 → 前端 readySet 大小 135（含别名映射）
- **109 / 764** 张前端卡片显示绿色"可执行"徽标
- 剩余 3 个后端算子不在前端卡片中（内部管线专用，如 `auto_tune_catboost`）

## 7. 统一 I/O 契约规则

所有算子严格遵守以下输入/输出约定：

| 场景 | 输入 key | 输出 key |
|------|---------|---------|
| DataFrame 流转 | `inputs["data"]` | `result["data"]` |
| 训练型算子 | `inputs["features"]` + `inputs["target"]` | `result["model"]` / `result["model_id"]` / `result["predictions"]` / `result["y_true"]` |
| 评估型算子 | `inputs["y_true"]` + `inputs["y_pred"]` | `result["score"]` (float) |
| 可视化算子 | `inputs["data"]` | `result["chart_option"]` (dict) + `result["chart_type"]` (str) |
| 数据输出算子 | `inputs["data"]` | `result["output_path"]` (相对路径) + `result["rows_written"]` (int) |
| 聚类算子 | `inputs["data"]` | `result["labels"]` (ndarray) |
| 异常检测算子 | `inputs["data"]` | `result["labels"]` + `result["scores"]` |
| 所有异常 | — | 统一抛 `OperatorExecutionError(op_id, error_type, msg)` |

## 8. 精度对比核心结论

### 8.1 故障诊断场景

**平台算子链路**（`extract_statistical_features` → `stratified_cv_eval`）vs **本地 release-3.1 代码**（`FeatureEngineer` + `RandomForest`）：

- 基础统计特征（max/min/mean）：**差值 < 0.001**
- std 差值略大（~0.03）：因 `np.nanstd(ddof=0)` vs pandas `groupby.std(ddof=1)` 的自由度差异
- 完整管线 **Accuracy/macro-F1 差 < 5%**（在允许范围内，随机性 + mRMR 特征选择顺序差异导致）

### 8.2 负荷预测场景

所有数值算子与 sklearn/scipy/numpy 精确对齐：

| 算子 | 基准 | 最大偏差 |
|------|------|---------|
| min_max_scale | sklearn.MinMaxScaler | < 1e-6 |
| z_score_scale | sklearn.StandardScaler | < 1e-6 |
| savgol_filter | scipy.signal.savgol_filter | < 1e-6 |
| stationarity_test | statsmodels.adfuller | < 1e-9（完全相同） |
| correlation_analysis | pandas.corr() | < 1e-6 |
| fft_transform | numpy.fft.rfft | < 1e-6 |
| arima | statsmodels.ARIMA.forecast | < 0.1% 相对误差 |
| smape_score / mse_rmse_mae | numpy 手算 | < 1e-6 |
| r2_score | sklearn.r2_score | < 1e-9 |
| isolation_forest | sklearn.IsolationForest | **逐元素完全相同** |
| confusion_matrix | sklearn.confusion_matrix | **逐元素完全相同** |

## 12. 总结

本次工作将 AIP 平台的算子库从"元数据壳子"推进到"可运行、可测试、可精度验证"的状态：

- **从 44 → 112**：翻了 2.5 倍的可用算子
- **从 0 → 109**：前端用户能一眼识别哪些算子真的能用
- **从无测试 → 254 个用例**：覆盖规范性、契约、性质、往返、端到端
- **从脚本验证 → 自动化对比**：用真实业务数据（负荷预测 + 故障诊断）持续验证精度

平台的下一步：用户可以直接在工作流编辑器里拖拽这 112 个算子搭建管线，不再受限于"只有负荷预测链路能跑"。
