# AIP 第七代前端重构汇报

## 结论

第七代前端重构建议把 AIP 从“功能菜单型后台”升级为“算法生命周期工作台”。新的核心路径是：

```text
行业场景 -> 推荐方案/模板 -> 工作流开发 -> AutoResearch 回测优化 -> 精度运营 -> 部署上线
```

这条路径能把现有行业场景、工作流编排、基础算法库、AutoResearch、精度运营和部署能力串成一个更自然的业务闭环。

## 为什么要改

当前左侧导航的问题不是功能缺失，而是功能组织方式已经跟不上平台能力：

- Agentic Service、算法服务、算法模板、部署、运营、精度运营分散在多个分组。
- 用户想做“开发一个算法并持续运营”，需要在多个菜单间跳转。
- 工作流、模板、AutoResearch、精度运营之间缺少统一入口。
- 左侧菜单像历史功能堆叠，不像面向用户任务的产品结构。

第七代要解决的是：让用户从“我要解决某个行业场景问题”自然进入“我要开发、回测、运营、上线一个算法”。

## 改成什么

推荐左侧导航结构：

```text
首页

行业服务
- 行业场景
- 算法方案库
- 行业数据管理
  - 数据源管理
  - 数据集管理
  - 人工标注审核

算法开发
- 算法管理
- 工作流编排
- 基础算法库
- 自动化回测
- 算法部署
- 算法运营

系统
- 系统管理
- 个人信息
```

其中：

- “算法管理”是新增默认首页。
- “自动化回测”对应现有 AutoResearch / baseline compare。
- “算法运营”对应现有精度运营。
- “算法部署”第一阶段先做占位。
- 旧功能不直接删除，先隐藏或保留路由兼容。

## 算法管理是什么

算法管理不是另一个模板库，而是一个“场景-算法-版本”的控制台。

它应该展示：

- 不同行业场景下已有算法工作流。
- 同一算法的开发 v1、v2、v3 等版本。
- 最近回测结果。
- 复验状态。
- 是否已进入精度运营。
- 是否待部署或已上线。

它提供操作：

- 新建算法工作流。
- 编辑工作流。
- 发起 AutoResearch。
- 进入算法运营。
- 进入部署占位页。

## 新建工作流怎么走

新建工作流建议使用向导式流程：

```text
点击新建工作流
-> 选择行业场景
-> 查看推荐模板
-> 选择基于模板创建 / 空白创建
-> 进入现有工作流编辑器
-> 保存为开发版本
-> 回到算法管理展示
```

推荐模板第一阶段不需要复杂 AI，先用规则匹配：

- 场景 ID。
- 标签。
- 工作流类型。
- 历史回测结果。
- 复验通过状态。

## AutoResearch 怎么打通

AutoResearch 不应只是独立页面。第七代中它应成为工作流版本的优化工具：

```text
算法管理
-> 选择工作流版本
-> 自动化回测
-> 候选版本
-> 多窗口复验
-> Promote
-> 回到算法管理形成新版本
-> 进入算法运营
```

第一阶段先做入口和参数打通，不强制改后端统一版本模型。

## 视觉流程怎么做

推荐使用这条流程：

```text
信息架构确认
-> Stitch 生成中保真原型
-> image2 迭代高保真视觉
-> 提取设计规约
-> Codex 实现
-> Playwright 截图验收
-> 视觉微调
```

核心判断：这条路线可行，但不能只把一张图交给 Codex。必须配套：

- 路由表。
- 页面模块说明。
- 数据字段。
- 组件状态。
- 响应式规则。
- 验收截图标准。

## 分阶段推进

### 第一阶段：规划和视觉

- 完成需求、设计、任务、视觉流程文档。
- 用 Stitch 做 2-3 个中保真方向。
- 用 image2 打磨一个高保真方向。
- 提取设计规约。

### 第二阶段：导航和路由

- 重构左侧导航。
- 新增 `/algorithm-dev/*` 路由。
- 保留旧路由。
- 隐藏 Agentic Service 默认入口。

### 第三阶段：算法管理首页

- 新增算法管理页。
- 读取现有工作流。
- 按场景归类。
- 展示开发版本和状态。
- 打通编辑、回测、运营、部署入口。

### 第四阶段：工作流创建和闭环

- 增加新建工作流向导。
- 接入推荐模板。
- AutoResearch 携带工作流上下文。
- 算法运营携带工作流或槽位上下文。

## 风险

- 现有工作流元数据可能缺少统一场景字段，需要前端兜底归类。
- 新旧路由并存会增加选中态和标题维护复杂度。
- AutoResearch、复验池、精度运营的版本状态还不是统一模型。
- 精度运营页面已有复杂逻辑，第一阶段不适合重写内部。
- 当前工作区很脏，实施必须小步补丁，不能顺手清理。

## 当前建议

先不要直接改代码。下一步应先进入视觉原型阶段：

1. 用 `visual-workflow.md` 生成 Stitch 提示词。
2. 产出 2-3 个中保真原型。
3. 选定方向后用 image2 打磨高保真。
4. 再进入 Codex 实现。
