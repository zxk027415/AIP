# 第七代前端视觉原型与像素级实现流程

## 结论

推荐采用以下流程：

```text
信息架构确认
-> Stitch 生成中保真原型
-> image2 迭代高保真视觉
-> 提取设计规约
-> Codex 实现
-> Playwright 截图验收
-> 视觉微调
```

不要直接把一张高保真图交给 Codex 实现。图片无法表达路由、数据结构、交互状态、空态、错误态和响应式规则。

## 当前中保真结论

当前已完成的中保真方向探索结论如下：

```text
主方向：A 平衡型控制台
增强点：吸收 B 强表格型工作台的高密度版本列表能力
```

已经细化的页面：

1. 左侧导航 + 算法管理首页框架。
2. 算法管理首页细化布局。
3. 新建算法工作流向导。

当前不选择纯 C 场景驱动型工作台作为主方向，原因是它更适合场景拓展，但第一阶段容易让主区过散、实现成本更高。

## 阶段 1：信息架构确认

目标：确定页面结构和业务路径，而不是追求视觉细节。

输入：

- 第七代导航结构。
- 算法开发模块页面清单。
- 算法管理首页核心模块。
- 工作流新建路径。
- AutoResearch / 精度运营 / 部署的入口关系。

输出：

- 页面清单。
- 路由表。
- 主用户路径。
- 每个页面的核心数据和操作。

## 阶段 2：Stitch 中保真原型

目标：快速生成 2-3 个可比较的信息架构方向。

建议生成页面：

1. 左侧导航重构后的整体框架。
2. 算法管理首页。
3. 新建工作流向导。
4. 自动化回测与工作流版本的衔接视图。

Stitch 提示词约束：

```text
这是工业 AI 算法平台，不是营销页。
目标用户是算法工程师、工业数据工程师和算法运维人员。
界面需要高信息密度、清晰状态、稳定导航。
使用 Ant Design 风格的工程控制台语义。
避免大面积渐变、装饰性插画、营销 hero、过度圆角。
重点展示算法工作流版本管理、行业场景筛选、回测状态、精度运营入口。
```

中保真原型验收：

- 是否能一眼看懂“行业服务”和“算法开发”的关系。
- 是否能从算法管理进入编辑、回测、运营、部署。
- 是否能容纳多个场景和多个版本。
- 是否保留足够信息密度。

## 阶段 3：image2 高保真打磨

目标：将选定中保真方向打磨成可实现的视觉稿。

image2 修改重点：

- 左侧导航密度和选中态。
- 算法管理页的场景分组。
- 版本状态标签：开发、候选、复验通过、生产、影子、退役。
- 表格/卡片的层级和操作按钮。
- 空状态和加载状态。
- 移动端折叠表现。

高保真稿约束：

- 页面主体不要使用嵌套卡片。
- 卡片圆角不超过 8px，除非全局设计系统另有要求。
- 控件优先用 Ant Design 常见模式。
- 按钮内文字必须完整显示。
- 不使用单一蓝紫渐变作为主视觉。
- 不牺牲信息密度换取装饰效果。

## 阶段 4：设计规约提取

高保真图定稿后，必须提取设计规约再交给 Codex。

每个页面需要记录：

```text
页面名称：
路由：
页面目标：
用户角色：
核心模块：
数据字段：
主要操作：
加载状态：
空状态：
错误状态：
权限/禁用状态：
桌面布局：
移动布局：
颜色规则：
字号规则：
间距规则：
组件清单：
验收截图：
```

算法管理页示例：

```text
页面名称：算法管理
路由：/algorithm-dev/management
页面目标：按行业场景管理算法工作流版本
核心模块：筛选区、统计区、场景分组、版本列表、操作区
主要操作：新建、编辑、回测、运营、部署
数据字段：workflow_id、name、scenario、version_tag、status、updated_at、mape、verification_status
空状态：无工作流时提示去新建
错误状态：加载失败时保留页面结构并提供重试
桌面布局：左侧固定导航，主区域 12 栅格
移动布局：筛选折叠，版本列表单列
```

## 阶段 5：Codex 像素级实现

Codex 输入材料：

- 高保真图。
- 设计规约。
- 路由表。
- 组件状态清单。
- 数据字段和兜底规则。
- 验收标准。

实现原则：

- 优先复用现有页面和 API。
- 先实现算法管理 MVP，再做视觉微调。
- 不删除旧页面代码。
- 不引入不必要依赖。
- 视觉改造控制在相关页面和局部样式内。

## 阶段 6：截图验收

建议验收视口：

- 桌面：1440 x 900。
- 窄屏：390 x 844。

验收内容：

- 左侧导航无文字溢出。
- 当前路由选中态正确。
- 算法管理页核心操作可见。
- 表格/卡片无遮挡。
- 空状态和错误状态可读。
- 移动端 Drawer 和内容不重叠。

验收命令建议：

```bash
cd frontend-sevice
npm run build
```

如启动本地服务做截图：

```bash
cd frontend-sevice
npm run dev
```

注意：启动服务可能热更新页面；若后端也以 reload 方式运行，后端代码改动可能影响运行中任务。本阶段优先只改前端。

## 交付物

视觉阶段结束后应交付：

- 中保真原型图。
- 高保真视觉图。
- 设计规约文档。
- Codex 实现任务清单。
- 截图验收记录。
