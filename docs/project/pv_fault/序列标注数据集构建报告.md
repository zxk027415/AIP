# 光伏故障序列标注数据集构建设计与质量报告

**当前数据集版本**：P0 网格化快照（`snap-20260813070141-c6165f`）；v3 历史结果保留用于方案对照  
**建设目标**：从 5 分钟粒度的功率、电流时序中构建逐点监督数据，使模型能够为每个采样点输出故障类型  
**当前阶段**：全天自然日网格数据集已构建并通过聚焦回归验证，待基于新快照重新训练/评估模型

## 一、建设背景

现有光伏故障数据与系统能力之间存在一个关键错位：**平台已经具备点粒度的标注、存储和模型训练能力，但历史数据主要只有天粒度标签，没有足够的点粒度真值。**

历史标签描述的是“某台设备在某一天属于哪一种故障”，无法直接回答故障在当天什么时间开始、持续到什么时间，以及故障前后的正常区间在哪里。对数据现状进行审计后发现，`point_labels`（逐点标签表）中 99.96% 的设备-天只有单一标签，本质上仍是将天级标签广播到全天；真正包含子天区间的精确标注只有 2 条操作记录、293 个采样点。

如果直接使用这些广播标签训练逐点诊断模型，模型只能学到“这一天属于某类故障”，却无法学习故障发生和恢复时的信号变化，也无法形成真正的点级诊断能力。因此，本次建设的核心不是简单整理已有标签，而是利用现有测量数据、天级故障信息和平台已有的点级能力，构造一套**有边界、有置信度、有质量门控、可追溯**的序列标注数据集。

## 二、建设目标与设计原则

### 2.1 建设目标

本次数据集建设需要同时满足四个目标：

1. **把天级故障信息细化为点级监督信号**：尽可能定位故障在一天内的实际发生区间，而不是整天广播。
2. **保留标签不确定性**：算法推断、人工确认和天级广播的可信度不同，不能作为同等真值使用。
3. **避免评估结果虚高**：清理全零、平线和重复序列，阻止同设备或增强副本同时进入训练集与验证集。
4. **与点粒度生产链路衔接**：数据集中的标签结构、时间粒度和样本形式应能直接支撑后续逐点训练、定时预测和人工回流。

### 2.2 设计原则

- **测量值与标签分离**：原始功率、电流时序保持不变，逐点标签独立管理。
- **点级真值优先**：人工确认的区间标签优先于算法推断，算法推断优先于天级广播。
- **弱标签不冒充强标签**：无法精确定位边界的数据可以保留，但必须降低训练权重。
- **增强数据只服务训练**：增强样本不得进入验证集或测试集。
- **全链路可追溯**：每条序列能够追溯到原始设备、日期、标签来源、可信层级和增强来源。
- **构建过程可复现**：构建参数、质量报告和版本指针随快照一并保存。

## 三、数据基础与总体方案

### 3.1 输入数据

数据集建设使用三类基础信息：

| 数据 | 作用 |
|---|---|
| 5 分钟粒度的设备功率、电流时序 | 提供模型输入，也是定位故障边界的原始波形 |
| 设备-天故障标签 | 提供当天已知的故障类型，限定点级细化时的类别范围 |
| 同站点同期设备数据 | 作为环境和天气基准，用于判断单台设备是否发生相对异常 |

天级标签虽然不能直接作为精确点级真值，但仍然有两个重要作用：一是确定该设备当天的故障类别，二是缩小边界搜索范围。数据集构建不重新猜测故障类型，而是在已有故障类型的前提下定位故障区间。

### 3.2 总体构建链路

```text
原始测量时序 + 设备-天故障标签
                ↓
        数据完整性与可用性检查
                ↓
      同站点同期设备建立参考基线
                ↓
      计算设备相对残差并生成候选段
                ↓
    置信度判定 / 人工确认 / 区间物化
                ↓
      形成逐点标签与标签可信层级
                ↓
        切分固定长度序列样本
                ↓
  平线过滤、有效点检查、去重与边界检查
                ↓
      按设备隔离划分训练与验证数据
                ↓
       仅对训练侧高质量样本做增强
                ↓
       发布版本化数据集快照与质量报告
```

这条链路将“已有天级标签”转换为“可供逐点模型学习的序列标签”，同时将每一步产生的不确定性保留下来，而不是在最终数据集中把所有标签伪装成同等可靠。

## 四、点级标签构建方法

### 4.1 从天级故障日中选择候选对象

首先以设备-天为单位检查原始时序。对于标签不为正常的设备-天，进入故障区间定位流程；正常设备-天则用于补充正常序列和构造同期参考基线。

进入后续流程前，需要确认序列具有足够的有效采样点。缺失过多、全天平线或无法建立同期参照的数据不参与边界推断，避免在低质量波形上生成伪精确标签。

### 4.2 使用同期设备建立动态参考基线

光伏功率会受到天气、辐照度和昼夜周期影响。只观察单台设备的绝对值，很难区分“全站因为天气一起下降”和“单台设备发生故障”。因此，本项目采用同站点同期对标方法：

1. 在同一站点、同一时刻选取其他可用设备；
2. 使用这些设备的中位数构造同期参考曲线；
3. 计算目标设备相对于参考曲线的残差；
4. 将持续偏离参考基线的连续区间识别为候选故障段。

实测中，99.5% 的设备-天能够找到至少 5 台同期设备作为参照，典型参考组约有 47 台设备。中位数对少量异常设备不敏感，因此比单设备阈值更能抵抗天气变化和个别噪声。

### 4.3 生成并确认候选故障区间

同期对标共生成 451 个候选故障段，其中高置信候选 233 段，中置信候选经裁判流程确认后保留 218 段，最终覆盖 194 个具有真实段边界的设备-天。

候选段确认后，按照已有天级故障类型将区间内采样点物化为对应故障标签，区间外采样点保持或补为正常标签。由此，一条原本“全天都是故障”的广播记录被转换成包含正常段、故障段和段边界的逐点标签序列。

对于无法可靠定位子天边界、但天级故障事实仍可信的数据，不强行制造边界，而是保留为整天故障弱标签。这样既保留可用数据，也避免把边界猜测误当作真值。

### 4.4 标签可信度分层

逐点标签按来源和确认程度划分为三个层级：

| `tier` — 标签可信层级 | 数据来源 | `sample_weight` — 样本训练权重 | 使用方式 |
|---|---|---:|---|
| `gold` — 金标 | 已确认的真实段边界 | 1.0 | 作为核心训练数据，允许受控增强 |
| `silver` — 银标 | 中置信候选经裁判流程确认 | 0.8 | 参与训练，但降低不确定标签的影响 |
| `bronze` — 铜标 | 整天故障或整天正常的广播标签 | 0.3 | 作为弱监督补充，不用于强化边界学习 |

训练时损失函数乘以 `sample_weight`（样本训练权重），使模型优先学习边界清晰、来源可靠的数据。可信度分层解决的是“标签质量不同但又不能全部丢弃”的问题，也是本数据集区别于简单天级广播数据的关键设计。

## 五、序列样本生成

### 5.1 样本结构

最终数据集中：

- `X` — 模型输入张量，形状为 `[2084, 120, 2]`；2084 条序列，每条 120 个时间点、2 个输入通道。
- `Y` — 逐点标签张量，形状为 `[2084, 120]`；每个输入时间点对应一个故障类别。
- 标签共覆盖 13 类，包括正常类和 12 类故障状态。

每条样本不是一个单独的天级类别，而是一段输入序列和一条等长标签序列。因此，同一条样本内部可以同时包含正常点、故障点和故障边界。

### 5.2 样本元数据

每条序列配套保存元数据，以支持训练控制、问题追踪和质量审计：

| 字段 | 中文含义与用途 |
|---|---|
| `tier` | 标签可信层级，用于区分金标、银标和铜标 |
| `sample_weight` | 样本训练权重，用于控制不同可信层级对损失函数的贡献 |
| `data_type` | 数据类型，如 `segment_boundary`（包含段边界）、`whole_day_fault`（整天故障）、`whole_day_normal`（整天正常） |
| `is_augmented` | 是否为增强样本；用于保证增强数据只进入训练侧 |
| `augment_method` | 增强方法，如 `jitter`（加噪）、`scaling`（幅值缩放）、`magnitude_warp`（幅值扭曲）或 `none`（未增强） |
| `source_idx` | 原始样本索引；增强样本通过它追溯到来源序列 |

### 5.3 受控数据增强

点级序列标注要求输入与标签严格对齐，因此只采用不会改变故障边界位置的增强方式：

- Jittering：加入小幅高斯噪声，当前噪声尺度为 σ=0.03；
- Scaling：对整条序列做 0.85～1.15 倍幅值缩放；
- Magnitude Warping：平滑改变局部幅值，不改变时间轴；
- Window Slicing：输入与标签同步裁剪时可使用。

不采用 Time Warping、Permutation、Mixup、SMOTE 或生成式样本，因为这些方法可能移动段边界、破坏时序连续性或生成不符合光伏物理规律的波形。

本版本对 194 条具有真实段边界的原始序列生成 776 条增强样本；弱标签数据不增强，避免放大标签噪声。所有增强样本均通过 `is_augmented`（是否为增强样本）显式标记，并从验证与测试数据中排除。

## 六、数据质量保障设计

数据质量治理贯穿标签生成、样本形成、数据划分和版本发布四个阶段，而不是只在数据集完成后做一次检查。

### 6.1 标签质量：防止弱标签冒充真值

- 真实段边界、算法候选和整天广播分别记录来源与可信层级；
- 对无法确认的区间不强行生成点级边界；
- 包含段边界的样本必须至少出现两种点标签，否则降级为整天类型；
- 训练时通过样本权重降低弱标签对模型的干扰。

### 6.2 波形质量：清理无诊断价值序列

初次审计发现 361 条全天全零或近似平线序列。这类数据通常来自停机或检修，不包含可学习的故障变化过程。不同设备的全零序列还形成了 115 对字节级完全重复样本，如果分别进入训练集和验证集，会造成评估虚高。

本版本设置以下门控：

| 质量规则 | 判定标准 | 处理方式 |
|---|---|---|
| 平线过滤 | value 通道标准差 < 0.1 | 丢弃序列 |
| 有效点检查 | 有效采样点少于序列长度的 50% | 丢弃序列 |
| 边界一致性 | `segment_boundary`（段边界类型）样本中标签种类少于 2 | 降级为整天类型 |
| 字节级去重 | `X.tobytes()` 的哈希发生冲突 | 只保留首条并记录审计结果 |

执行门控后，361 条低信息序列被移除，115 对字节级重复全部消除。当前快照中无平线型 trivial anomaly，也无字节级重复。

### 6.3 划分质量：阻止设备指纹和增强副本泄漏

同一设备不同日期的波形具有相似的物理特性。如果同一设备同时出现在训练集和验证集，模型可能依靠设备指纹而不是故障规律获得高分。因此，本项目采用按设备隔离的 5 折交叉验证：同一设备的所有原始序列和增强副本只能出现在同一侧。

增强样本在完成设备分组后才加入训练侧，验证集与测试集只使用未增强原始样本。最终指标报告交叉验证的均值和标准差，降低单次随机划分带来的偶然性。

### 6.4 类别质量：保留真实分布，训练侧处理不平衡

当前数据最大类别与最小类别的点数比例为 786:1，属于极端类别不平衡。其中正常类有 94,357 个点，占 37.7%；最少的 label=9 只有 120 个点，占 0.05%。

本项目不通过删除正常点来人为平衡数据，因为正常段是故障边界的必要组成部分。类别不平衡主要在训练和评估阶段处理：

- 使用 Focal Loss（γ=2）降低大量容易正常点的梯度贡献；
- 使用 WeightedRandomSampler（加权随机采样器）提高少数类序列在训练批次中的出现机会；
- 主报告单独给出主要 7 类指标，全量审计同时保留 13 类指标；
- label=9、10、16 等极稀有类别单独展示，不用极少样本的偶然结果代表整体能力。

这种做法保留了真实时序和段边界，不通过不符合物理规律的合成数据制造表面平衡。

### 6.5 版本质量：保证可追溯和可复现

数据集采用快照方式发布：

```text
data/seq_annotation_datasets/
├── registry.json
└── snapshots/
    └── snap-20260812-xxx/
        ├── dataset.npz
        ├── meta.parquet
        ├── build_config.json
        └── build_report.json
```

各文件职责如下：

- `registry.json` — 数据集版本登记文件，保存当前启用快照的指针，使训练程序不必写死具体快照目录。它与样本文件分开保存，作为数据集发布入口；当前按数据集族登记，具体版本由快照 ID 分区。
- `dataset.npz` — 模型输入 `X`（输入序列张量）和逐点标签 `Y`（标签序列张量）。
- `meta.parquet` — 样本元数据，保存来源、可信层级、权重和增强追溯关系。
- `build_config.json` — 构建配置，记录本次生成使用的阈值和参数，用于复现。
- `build_report.json` — 构建质量报告，记录过滤、去重、类别分布和门控结果。

所有路径均为相对于项目或运行配置的数据目录，不依赖某台开发机的绝对路径。

## 八、与点粒度诊断链路的衔接

本数据集不是独立于生产系统的一次性实验产物，而是点粒度诊断闭环中的训练侧基础。

训练阶段，模型学习的是长度一致的测量序列到逐点标签序列的映射；预测阶段，系统可以对设备在上次预测时间与本次统一诊断截止时间之间的新到点执行同样的序列化处理，并输出每个采样点的故障类型。尚未到达的数据不需要补造，可留到下一次调度周期与后续到达点一起诊断。

预测结果本身不直接成为训练真值。只有经过人工确认或受控裁判流程确认的区间，才会回写为新的逐点标签，并在下一次数据集构建时按来源进入 gold 或 silver 层。由此形成以下闭环：

```text
点级数据集 → 序列标注模型 → 定时点级预测
     ↑                            ↓
版本化重建 ← 已确认标签回流 ← 人工复核/裁判
```

这保证了“点级预测能力”和“点级训练真值”可以持续共同演进，同时避免模型预测未经确认便污染训练数据。

## 九、当前边界与后续建设

当前 v3 数据集已经解决了从天级标签到点级序列监督的可行性问题，但仍存在以下边界：

1. **精确段边界数量仍有限**：目前只有 194 个设备-天具备真实段边界，需要通过预测复核闭环持续积累。
2. **极稀有类别证据不足**：label=9、10、16 等类别样本过少，暂时不能仅凭单次交叉验证结果判断泛化能力。
3. **跨站点泛化仍需验证**：后续应使用完全未参与训练的新站点作为独立测试集。
4. **中置信标签仍需持续复核**：可结合变点检测与 LLM 裁判缩小人工确认范围，但最终仍应保留来源和审计记录。
5. **生产回流必须保持真值门槛**：预测记录与确认标签分开存储，只有经过确认的结果才能进入下一版训练快照。

后续建设重点不是继续无约束扩大样本数量，而是优先增加真实段边界、补充稀有故障类型，并用跨设备、跨站点的独立数据验证模型是否真正学到了可迁移的故障规律。

## 十、结论

本次数据集建设解决的根本问题，是在“系统已经具备点级诊断能力、历史数据却主要停留在天级标签”的条件下，建立一条可信的点级训练数据生产链路。

该链路不是将天级标签简单广播到每个采样点，而是通过同站点同期对标定位候选故障段，通过确认流程和可信度分层管理标签不确定性，再通过平线过滤、重复清理、设备隔离、增强隔离和版本化快照保证数据质量。最终形成 2,084 条长度为 120、输入标签逐点对齐的序列样本，并覆盖 13 类状态。

因此，v3 的价值不只在于数据量增加，而在于数据已经具备三个关键属性：**模型能够学习段边界、评估结果不依赖明显泄漏、每条样本都能追溯其来源与可信程度。** 这为后续逐点模型训练、统一时刻诊断和人工确认回流提供了可持续的数据基础。

## 十一、v4 修正：全天 288 点严格校验（2026-08-13）

v3 采用 `seq_len=120`（仅白天 07:00~17:00），模型从未见过夜间波形，无法形成全天诊断能力。v4 将序列长度统一为 **288 点全天（24h × 12 点/h）**，并引入严格的全天网格校验，防止半日序列被误标为全天。

### 11.1 为什么必须 288

- 生产链路按全天 288 点构建序列（`cumulative_training.py` 调 `build_dataset(seq_len=288, ...)`），训练侧与生产侧必须同口径，否则推理时模型输入与训练分布不一致。
- `trained_full_day` 门控要求 `seq_len==288` 且数据集明确 `full_day_grid_validated=True`，半日补零序列会导致该校验失败，模型无法按全天部署。
- 夜间虽然物理上大多正常（value≈0、i_cal≈0），但模型需要学习"夜间全零波形 = label 0"，否则白天故障段设备在夜间会被误判。

### 11.2 最终决策：288 是模型输入长度，不是原始行数门槛

前期 dry-run 曾尝试以 `min_points=288`（原始点数至少 288）换取严格全天标志，但数据审计证明这个口径错误：许多物理完整自然日在夜间按 10 分钟采样，原始行数通常只有 204～220；点粒度金标 196 个设备-天中，恰好 288 行的只有 30 个（15.3%）。如果按原始行数卡 288，会误删约 85% 的边界数据。

P0 最终改为先铺设 `00:00, 00:05, ..., 23:55` 共 288 个时钟槽，再按真实覆盖证据门控：

| 字段 | 中文含义 | 最终值 |
|---|---|---:|
| `seq_len` | 模型固定输入槽数，不再代表原始行数 | 288 |
| `min_occupied_slots` | 288 槽中至少有多少个实测槽 | 173（约 60%） |
| `min_daytime_occupancy` | 07:00～17:00 白天实测占有率下限 | 0.8 |
| `max_daytime_gap_slots` | 白天允许的最长连续空槽 | 6（30 分钟） |
| `is_measured` | 第三输入通道；1 表示实测、0 表示插补或夜间填零 | 0/1 |

夜间空槽按物理先验填 0；白天短缺口只在门槛内做线性插值；超过 30 分钟的白天连续缺口直接拒绝。为确保 `full_day_grid_validated` — 全天网格已由真实覆盖证据验证 — 可诚实置为 true，构建器还会剔除任一小时完全没有实测槽的边缘日，而不是放松全天判定。

### 11.3 夜间标签处理策略

`_load_one_indexed` 对夜间（hour < 7 或 ≥ 17）逐点裁决：

```text
夜间 point_labels 来源 ∈ {human_range, human_day, cluster}（显式源）→ 保留原标签
夜间其他来源（day_label / pseudo 等低置信天级广播）          → 强制置 0（正常）
整天故障天（whole_day_fault）                                → 夜间置 0（fault_daylight_only）
```

这保证了"夜间物理正常 = label 0"的物理语义，同时不丢弃显式标注的夜间故障（如漏电）。

### 11.4 v4 数据集质量审计（无穿越）

对 `snap-20260813023128-47e0c8`（927 序列 / 288 点 / 10 类）逐项实证：

### 11.5 消融结论（CE vs Focal Loss + WeightedSampler）

配置：288 全天数据集 / `unet1d_wide` / 40 epochs / 按设备分组 2 折（test 30%）。

| 配置 | 模型 | 折 1 (seed 42) | 折 2 (seed 43) | primary_f1 (mean±std) | binary_f1 (mean±std) |
|---|---|---|---|---|---|
| A: CE 基线（class_weight + 均匀采样） | unet1d_wide | 0.3209 / 0.7741 | 0.3328 / 0.7909 | **0.3268 ± 0.0059** | **0.7825 ± 0.0084** |
| B: FocalLoss(γ=2) + WeightedRandomSampler + sample_weight | unet1d_wide | 0.2258 / 0.7276 | 0.2418 / 0.7562 | **0.2338 ± 0.0080** | **0.7419 ± 0.0143** |

**结论：CE 基线显著优于 Focal Loss + WeightedSampler**（primary_f1 差 +0.093，binary_f1 差 +0.041，两折一致），与 5 epochs smoke 方向一致（smoke：CE 0.21~0.29 / Focal 0.09~0.12）。

**解释**：本数据集夜间已全部清零为 label 0，正常点占比高（76.7%），其中夜间正常点占比尤其大。Focal Loss 刻意压低"易分正常点"的梯度，在夜间已清零的标签设计下反而把大量正常的夜间波形压得过低，损害整体判别；CE + class_weight 在这种标签下更平衡。**保持默认训练策略（CE）不改，与「仍不改默认训练策略」的约束一致。**

> 说明：本机 Windows 上 bilstm/transformer 与 Focal 训练出现过 torch 多线程死锁（已加 `OMP_NUM_THREADS=1` + `torch.set_num_threads(1)` 缓解）。unet 是 3 个模型中唯一稳定跑通两折的；完整 3 折 × 3 模型对照建议在 GPU 服务器补跑。

## 十二、P0 网格化实施结果与验收（2026-08-13）

### 12.1 缺口、修复与字段链路

旧链路按行截断或在尾部补零，使同一数组下标在不同采样密度下对应不同时间。例如下标 144 在标准自然日代表 12:00，在夜间 10 分钟采样的稀疏日却可能对应 15:10；这是时间轴错位，不是普通缺失值问题。

P0 将链路统一为：

```text
构建 CLI 的覆盖参数
→ build_dataset（数据集构建器）
→ align_day_to_grid（训练/推理共享网格对齐函数）
→ dataset.npz / build_config.json / build_report.json
→ SeqAnnotationTrainer（训练归一化与模型工件）
→ SeqAnnotationPredictor（按同一 grid_contract 推理）
```

关键字段流转如下：

| 字段 | 构建侧默认 | 最终消费位置与行为 |
|---|---:|---|
| `min_occupied_slots` — 全天最少实测槽数 | 173 | `align_day_to_grid` 不满足时返回 `occupancy_below_threshold` — 总覆盖率不足 |
| `min_daytime_occupancy` — 白天实测占有率下限 | 0.8 | 对白天覆盖不足的设备-天拒绝构建与推理 |
| `max_daytime_gap_slots` — 白天最长连续空槽 | 6 | 超过时返回 `daytime_gap_too_long` — 白天缺口过长 |
| `is_measured` — 实测/补值掩码通道 | 派生值 | trainer 与 predictor 均跳过 z-score；jitter 只修改 mask=1 的槽 |
| `grid_contract` — 网格契约 | 写入快照和模型 metadata | predictor 读取后复用训练门槛；旧工件无此字段时继续走旧兼容路径 |
| `full_day_grid_validated` — 全天网格验证结果 | 必须由原始样本真实小时覆盖证明 | trainer 与累计训练服务共同决定 `trained_full_day` — 模型是否具备全天发布资格 |

缺省行为明确为：旧请求不传新门槛时使用 173 / 0.8 / 6；旧两通道模型仍可推理；新模型默认启用网格对齐并自行派生 mask，不要求 API 调用方上传 `is_measured` 列。

### 12.3 防穿越与标签安全

- 训练和推理共用同一个 `align_day_to_grid` — 自然日网格对齐函数，不存在两套补值口径。
- 白天插值只使用同一天的相邻实测点，不读取未来日期、其他验证设备或全局统计量；它使用的是单条完整日序列上下文，不构成跨样本数据穿越。
- 标签空槽只有在左右最近实测标签一致时才补该类；白天只有单侧证据或两侧类别冲突时写 `IGNORE_LABEL` — 训练忽略标签，避免凭空扩大故障段。
- 夜间弱天级故障仍清零，显式人工区间标签保留；插补点由 `is_measured=0` 明示，模型不必通过“恰好为 0”猜测缺失状态。
- 数据增强不移动时间轴；mask 不参与缩放/扭曲，jitter 不污染插补槽。
- 训练归一化按单序列执行，mask 保持 0/1；设备隔离切分和增强样本不进测试集的既有防泄漏规则保持不变。
