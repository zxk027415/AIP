# 第七代前端重构 Stitch 提示词

## 使用目标

本文件用于生成第七代前端重构的中保真原型。目标不是做营销视觉，而是快速探索信息架构、导航关系、算法管理首页结构和工作流创建路径。

## 全局约束提示词

```text
这是一个工业 AI 算法平台的业务后台，不是营销官网。
目标用户是算法工程师、工业数据工程师、算法运维人员。
请输出中保真产品原型，不要做高保真营销视觉。

风格要求：
- 工程控制台风格
- 高信息密度，但结构清晰
- 使用 Ant Design 风格的后台语义
- 左侧导航稳定、可扫描、适合高频操作
- 避免大面积渐变、装饰插画、营销 hero、过度圆角、浮夸卡片
- 页面主体以表格、分组、状态标签、筛选条、操作按钮为主

业务主线：
行业场景 -> 推荐方案/模板 -> 工作流开发 -> AutoResearch 回测优化 -> 精度运营 -> 部署上线

页面重点：
- 左侧导航重构
- 算法开发模块
- 算法管理首页
- 工作流新建向导
- AutoResearch 与工作流版本衔接
- 精度运营入口整合
```

## 原型方向 A：平衡型控制台

```text
请生成一个工业 AI 算法平台第七代前端中保真原型。

导航结构：
- 首页
- 行业服务
  - 行业场景
  - 算法方案库
  - 行业数据管理
- 算法开发
  - 算法管理
  - 工作流编排
  - 基础算法库
  - 自动化回测
  - 算法部署
  - 算法运营
- 系统

默认首页为“算法管理”。

算法管理页内容：
- 顶部：场景筛选、搜索、状态筛选、新建算法工作流按钮
- 中间：统计卡片（场景数、工作流数、开发版本数、运营中版本数）
- 主体：按行业场景分组展示已有工作流模板
- 每个工作流展示：名称、开发 v1/v2/v3、回测状态、复验状态、运营状态、操作按钮（编辑、回测、运营、部署）

请做一个平衡型后台原型：
- 左侧导航占比适中
- 主区采用分组卡片 + 紧凑表格混合
- 强调“从场景到版本管理”的路径
```

## 原型方向 B：强表格型工作台

```text
请生成一个工业 AI 算法平台第七代前端中保真原型。

重点不是卡片展示，而是高密度工作台。

导航结构同上。

算法管理页内容：
- 顶部筛选栏和快捷操作栏
- 一个场景切换器
- 主体以表格为核心
- 表格列：场景、算法名称、版本、最近回测、复验状态、生产状态、更新时间、操作
- 支持展开某一算法查看开发 v1/v2/v3

请做成偏运营控制台风格：
- 信息密度高
- 更像版本管理面板
- 用标签、状态点、紧凑按钮表达状态
- 减少装饰性卡片
```

## 原型方向 C：场景驱动型工作台

```text
请生成一个工业 AI 算法平台第七代前端中保真原型。

导航结构同上。

页面重点是“从行业场景进入算法开发”。

算法管理页内容：
- 顶部展示当前场景切换栏
- 主区优先展示场景分组
- 每个场景下展示推荐模板、已有工作流版本、AutoResearch 入口、算法运营入口
- 更强调“场景 -> 模板 -> 版本”的视觉层级

请做成场景驱动型后台原型：
- 主区按场景分区
- 场景块清楚，但不要营销化
- 保持工程工作台感
- 适合后续扩展更多行业场景
```

## 工作流新建向导补充提示词

```text
请单独生成“新建算法工作流”中保真原型。

流程：
1. 选择行业场景
2. 查看系统推荐模板
3. 选择“基于模板创建”或“空白创建”
4. 进入工作流编辑器

要求：
- 用分步向导或弹窗
- 每一步都非常清楚
- 推荐模板卡片要体现适用场景和模板类型
- 空白创建作为次选项存在
- 保持工程后台风格，不要像电商购买流程
```

## AutoResearch 衔接页补充提示词

```text
请单独生成“算法管理 -> 自动化回测”衔接页的中保真原型。

要求：
- 从某个工作流版本发起 AutoResearch
- 页面中能看到 baseline、候选版本、复验状态、Promote 状态
- 能返回算法管理
- 能进入算法运营
- 重点是版本状态流转，不是论文式实验展示
```

## 推荐使用方式

1. 先分别生成 A/B/C 三个方向。
2. 选一个主方向。
3. 再对该方向做局部改稿：
   - 左侧导航
   - 算法管理页
   - 新建工作流向导
   - AutoResearch 衔接页
4. 确定中保真后再进入 image2 高保真。
