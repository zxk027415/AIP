# 数据穿越检测报告

## 1. 背景与目标

在时序预测的回测（Backtest）中，**数据穿越（Data Leakage）** 是最常见也最隐蔽的问题：如果特征构造或模型训练过程中不小心使用了预测时刻之后的真实数据，回测精度会虚高，但实际部署时效果会大幅下降。

本报告针对 `run_weihai_backtest.py` 的滚动回测流程，设计了一套系统性的数据穿越检测方案，覆盖特征工程、数据切分、交叉验证等多个环节。

---

## 2. 检测方案设计

### 2.1 检测对象

威海负荷预测滚动回测流程，具体参数：
- 数据范围：2025-07-02 ~ 2026-04-07（15 分钟粒度，26867 行）
- 检测场景：预测日 = 2026-04-01，训练期 = 2026-03-01 ~ 2026-03-31
- 训练集：2881 行，测试集：96 行（1 天 × 96 个点）

### 2.2 八项检测及原理

| 编号 | 检测项 | 检测原理 |
|------|--------|----------|
| 1 | 特征穿越检测（扰动法） | 将预测日的 load 真值替换为随机值，重新计算特征。如果测试集的某个特征值发生变化，说明该特征依赖了预测日的真实 load |
| 2 | 训练集/测试集时间边界 | 验证训练集所有时间戳 <= train_end，测试集所有时间戳 >= pred_day，两者无重叠 |
| 3 | 日统计特征穿越 | 验证测试集的 day_mean 等日统计特征等于 train_end 当天（而非预测日当天）的统计值，确认 shift(1) 生效 |
| 4 | 交叉验证穿越 | 验证 TimeSeriesSplit 每一折的验证集索引严格大于训练集索引，不存在"用未来数据训练、用过去数据验证"的情况 |
| 5 | Lag 特征逐行验证 | 对测试集每一行，检查 lag 特征引用的时间点是否在预测日之前。如果引用了预测日之后的时间，特征值必须为 NaN |
| 6 | Diff 特征穿越 | 用扰动法精确检测 diff_1、diff_96、diff_192 是否依赖预测日的 load 值 |
| 7 | Rolling 特征穿越 | 手动计算测试集第一行的 roll_4_mean，验证 rolling(center=False) 确实只使用了历史数据 |
| 8 | 训练集目标变量 | 验证 y_train 不包含预测日及之后的 load 值 |

### 2.3 扰动法详解（检测 1 和 6 的核心方法）

扰动法是最强力的穿越检测手段，原理如下：

```
步骤 1：用原始数据构建特征 → 记录测试集每个特征的值
步骤 2：将预测日及之后的 load 替换为 load × 10 + 随机噪声
步骤 3：用扰动后的数据重新构建特征
步骤 4：对比测试集特征值：
        - 如果某特征值变了 → 该特征依赖了预测日的 load → 穿越！
        - 如果某特征值没变 → 该特征只依赖历史数据 → 安全
```

这个方法的优势是**不需要理解特征的计算逻辑**，纯黑盒检测。

### 3.1 穿越根因分析

**核心问题在 diff 特征的构造方式：**

```python
# run_weihai_backtest.py 中的 build_features()
load_prev = feat[load_field].shift(1)       # t-1 时刻的 load
feat["diff_1"] = load_prev - load_prev.shift(1)  # load[t-1] - load[t-2]
```

回测流程中，`combined = pd.concat([train_raw, test_raw])` 将训练集和测试集合并后再做特征工程。此时 test_raw 的 load 列包含预测日的**真实负荷值**。

对于测试集第 2 行（04-01 00:15）：
- `load_prev = load.shift(1)` → 取的是 04-01 00:00 的 load → **这是预测日的真实值，在实际预测时是未知的！**
- `diff_1 = load_prev - load_prev.shift(1)` → 使用了未来数据

**穿越链路：**
```
test_raw 的 load 列带真实值
  → pd.concat 合并到 combined
    → load.shift(1) 在测试集内部引用了测试集的 load
      → diff_1 / diff_96 / diff_192 使用了预测日的真实负荷
        → 数据穿越！
```

## 4. 修复方案

### 4.1 修复内容

在 `run_weihai_backtest.py` 的 `rolling_backtest()` 函数中，合并数据前将测试集的 load 列置为 NaN：

**修复前：**
```python
combined = pd.concat([train_raw, test_raw], ignore_index=True)
```

**修复后：**
```python
test_raw_masked = test_raw.copy()
test_raw_masked["load"] = np.nan
combined = pd.concat([train_raw, test_raw_masked], ignore_index=True)
```

### 4.2 修复原理

将测试集的 load 置为 NaN 后：
- `load.shift(1)` 在测试集范围内取到的是 NaN → diff 特征变为 NaN → 不含未来信息
- `load.shift(96)` 在测试集范围内取到的是训练集最后一天的 load → lag 特征正确引用历史
- 训练集部分完全不受影响（NaN 只在测试集范围内）
- 测试集中值为 NaN 的特征在后续会被 `fillna(0)` 处理，不影响模型输入

### 4.3 修复的影响范围

| 特征类别 | 修复前 | 修复后 |
|----------|--------|--------|
| 时间特征（hour, dayofweek 等） | 不受影响 | 不受影响 |
| Lag 特征（lag_1d ~ lag_28d） | lag_1d 在测试集内引用了预测日 load | lag_1d 在测试集内为 NaN → fillna(0) |
| Diff 特征（diff_1, diff_96 等） | **穿越**：使用了预测日 load | 测试集内为 NaN → fillna(0) |
| Rolling 特征（roll_*_mean 等） | 基于 shift(96)，不受影响 | 不受影响 |
| 日统计特征（day_mean 等） | 基于 shift(1) 按天，不受影响 | 不受影响 |

## 6. 结论

1. **发现了 1 处真实的数据穿越**：diff 特征（diff_1、diff_96、diff_192）在测试集内部通过 `load.shift(1)` 引用了预测日的真实负荷值。

2. **修复方案简洁有效**：合并数据前将测试集 load 列置为 NaN，一行代码修复，不影响训练集特征，不改变模型架构。

3. **修复后 8 项检测全部通过**，确认回测流程不再存在数据穿越。

4. **其他环节设计合理**：
   - TimeSeriesSplit 交叉验证正确避免了时间穿越
   - 日统计特征的 shift(1) 正确使用了前一天的统计量
   - Rolling 特征的 center=False 确保只使用历史窗口
   - 训练集目标变量不包含未来数据
