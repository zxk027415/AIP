# Gap 逻辑预测实验报告

## 1. 实验背景

### 1.1 问题提出

在实际业务中，D 日执行预测时，D 日当天的负荷数据往往尚未采集完成或存在入库延迟，模型实际只能使用 D-1 及之前的历史真值。如果回测中假设"D 日能拿到 D-1 的完整数据"，则回测精度会高于实际上线精度，构成一种**隐性的数据穿越**——不是特征层面的穿越，而是对数据可用性的过度假设。

### 1.2 两种预测逻辑对比

| | NoGap（原方式） | Gap（新方式） |
|---|---|---|
| 预测执行日 | D | D |
| 预测目标日 | D+1 | D+1 |
| 数据可用截止 | D-1（含 D-1 当天） | D-2（含 D-2 当天，跳过 D-1） |
| Lag 特征起算 | lag_1d（前 1 天） | lag_2d（前 2 天） |
| 日统计特征 | shift(1)（前 1 天统计量） | shift(2)（前 2 天统计量） |
| 业务真实性 | 假设 D 日能拿到 D-1 数据 | 符合实际数据延迟场景 |

以预测 2026-04-01 为例：

```
NoGap: 3/31 执行预测，用到 3/31 23:45 的数据 → 预测 4/1
Gap:   3/31 执行预测，只用到 3/30 23:45 的数据 → 预测 4/1（中间 gap 3/31 一整天）
```

## 2. 实验设计

### 2.1 数据穿越验证

对 Gap 逻辑执行了 6 项系统性穿越检测：

| 检测项 | 结果 |
|--------|------|
| 数据截取边界（D 日和 D+1 日 load 全为 NaN） | PASS |
| 扰动 D 日 load（测试集特征是否变化） | PASS |
| 扰动 D+1 日 load（测试集特征是否变化） | PASS |
| Lag 特征引用时间（所有引用 ≤ D-1） | PASS |
| 训练集 y_train 时间边界（严格 < D 日） | PASS |
| 日统计特征 shift(2) 验证 | PASS |

**6 项检测全部通过，Gap 逻辑无数据穿越。**

### 2.2 回测配置

- 回测期间：2026-04-01 ~ 2026-04-07（7 天）
- 训练窗口：30 天
- 模型：XGBoost + LightGBM + CatBoost + Ridge（自适应加权集成）
- 交叉验证：TimeSeriesSplit（5 折）
- 超参优化：贝叶斯优化

## 5. 可行性分析

### 5.1 精度损失评估

| 维度 | 数值 | 评估 |
|------|------|------|
| 7 天平均 SMAPE 差异 | +0.32% | 可接受 |
| 精度损失率 | 14.3% | 中等 |
| 4/1 单日差异 | +0.09% | 极小 |
| 最差单日差异（4/2） | +1.20% | 可接受 |
| Gap 胜出天数 | 2/7 | 特定场景有优势 |

### 5.2 核心判断

**Gap 逻辑是否需要，取决于一个事实问题：D 日做预测时，能否拿到 D-1 的完整数据？**

- 如果**能拿到**（数据 T+1 凌晨入库）→ 不需要 gap，NoGap 即可
- 如果**拿不到**（数据有延迟）→ **必须用 gap**，否则回测精度是虚假的

根据实际项目经验，D 日很难获取到当日的完整数据，因此 Gap 逻辑是必要的。

### 5.3 Gap 逻辑的优势

1. **回测精度 = 上线精度**：不会给领导虚假预期，避免"回测很好、上线变差"的尴尬
2. **无数据穿越**：6 项检测全部通过，从数据可用性层面也杜绝了穿越
3. **精度损失可控**：7 天平均仅 +0.32%，不影响业务判断
4. **特定场景更优**：在季节转换期和休息日，Gap 甚至可能比 NoGap 更好

### 5.4 Gap 逻辑的代价

1. 精度平均下降 0.32%（约 14%）
2. Lag 特征从 lag_2d 起算，丢失了最近一天的信息
3. 日统计特征延迟一天（用 D-2 的统计量而非 D-1）

## 6. 结论与建议

1. **Gap 逻辑可行**，精度损失在可接受范围内
2. **建议回测程序采用 Gap 逻辑**，确保回测结果反映真实业务精度
3. 可通过配置参数（如 `GAP_DAYS=1`）控制 gap 天数，保留灵活性
4. 后续如果数据采集延迟改善（如实现 T+0 入库），可将 `GAP_DAYS` 设为 0 切回 NoGap 模式
