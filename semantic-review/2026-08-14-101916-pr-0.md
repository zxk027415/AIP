## 逐点详情白名单在持久化前删除 raw 版本 [confirmed]

`SeqAnnotationPredictor.predict_device_day()` — 输入单设备单自然日测量表，输出天级摘要、逐点标签、置信度和分段，先产生 `raw_point_predictions`，再按 metadata 的 `postprocessing` 执行 7–17 外归正常、短故障删除和同类裂缝合并。它用处理后业务标签反查类别索引并读取 `point_confidences` — 处理后逐点类别对应概率；旧工件缺契约时 `enabled=false`，raw 与 processed 一致。

`_run_seq_annotation_prediction_cycle()` 把这些字段放进 `prediction_detail`，但随后 `_normalize_predictions()` 仅复制 `timestamps`、`point_predictions`、`point_confidences`、`segment_predictions` 等字段，没有复制 `raw_point_predictions` 或 `postprocessing`（`backend-service/services/scheduler/tasks/pv_fault_tasks.py:614-641, 872-883`）。`_write_prediction_batch()` 写入的是截断对象；`get_unit_timeseries()` 构造 `prediction_overlay` — 波形页逐点叠加数据时也只返回处理后字段（`backend-service/api/iterative_labeling.py:1612-1621`）。双版本在持久化入口前已退化成单版本。

## 幂等检查把跨存储失败变成永久缺少批次 [confirmed]

seq scheduler 先调用 `insert_prediction_record()` 提交数据库记录，再写完整点级批次、创建审核会话，最后 upsert `DevicePredictionCursor` — 每设备预测水位（`pv_fault_tasks.py:925-1005`）。后三步任一失败时，数据库行已存在，详情引用的 `batch_id` 可能没有对应文件。

下一轮按 `(site_id, device_id, branch_id, business_date, sample_id)` — 站点/设备/支路/业务日/样本键跳过已有记录；若全部存在，函数在写批次前以 `all_duplicate` 返回（同文件 `909-970`）。失败重试不能补写 raw/postprocessed 详情、重建审核会话或推进游标，cron 会持续重复计算同一天。

## “全天”门控没有验证最终 seq 方案 [confirmed]

API 用环境变量覆盖 `model_name` — 模型架构、`segment_boundary_weight` — 段边界有效点 loss 倍数、`postprocessing_enabled` — 是否后处理和 `postprocess_min_fault_segment_points` — 最短故障段槽数（`backend-service/api/iterative_labeling.py:643-658`）。默认值是 bilstm_attn、4、true、3，训练器固定 CE 并从快照读取 channels，但这些是默认值，不是生产准入。

`CumulativeTrainingService.set_modeling_paths()` — 输入生产/备选路径并更新生产引用，只检查 seq 登记项存在且 `trained_full_day=true`（`backend-service/services/iterative_labeling/cumulative_training.py:630-657`）。scheduler 加载后也只检查 `supports_night` 和 `seq_len==288`（`pv_fault_tasks.py:775-785`）。禁用后处理、权重 1、阈值 1 或其他架构的工件仍可 Promote；新 schema 的晋升边界需要核验 metadata/`sequence_contract`。

## 未标注候选查询破坏整日模型输入 [confirmed]

`query_unlabeled_by_point_labels()` — 输入设备和时间范围，输出没有有效 `PointLabel` 的测量行，通过 `where(~labeled_exists)` 排除已有人工标签时刻（`backend-service/services/db/repositories/pv_fault.py:381-397`）。seq scheduler 把返回值按日期分组后直接传给 predictor；三通道中的 `is_measured` 应表示真实缺测/插补，不应把“已有标签”变成“没有测量”。

短框选会被插值掩盖，长框选会超过 `max_daytime_gap_slots` 并整日拒绝；若标签覆盖大量槽位，该日甚至不会进入查询结果。应先用未标注事实选出待预测设备日，再回查该自然日全部 `training_samples` 构造模型输入。

## 288 点实验指标可能使用生产不会执行的后处理 [confirmed]

trainer 的 `_evaluate()` 在 `Y.shape[1] == 288` 时启用后处理，没有读取 `full_day_grid_validated` 或最终 `trained_full_day`（`backend-service/services/iterative_labeling/seq_annotation/trainer.py:395-405`）。metadata 只有在 288 槽、`daylight_hours=[0,24]` 和严格网格证据同时成立时才启用 artifact 后处理（同文件 `199-208`）。

因此全天证据失败的 288 点实验模型会登记处理后的 `macro_f1_mean`、`point_accuracy`，predictor 加载同一工件却返回 raw 标签。即使它不能通过当前全天门控，人工比较仍使用不可复现指标；评估应使用预先算出的最终工件契约。
