## High-level view

## 生产模型登记绕过统一准入且暴露为无认证写接口 [confirmed]

`assert_final_sequence_contract()` — 输入工件 metadata 或训练返回的 `sequence_contract`，输出原契约或抛出差异错误 — 已用于显式路径切换、fallback 切换和 scheduler 实际工件加载。其校验覆盖 `bilstm_attn`、`[value, i_cal, is_measured]`、288 槽全天网格、`cross_entropy`、`segment_boundary` 四倍权重，以及 enabled 的 7–17/3 槽后处理（`backend-service/services/iterative_labeling/seq_annotation/production_contract.py:10-76`）。

`register_path_model()` — 输入路径 key、模型引用和可选指标，更新该路径最近模型登记 — 却会无条件重写 `path_models[key]`；key 等于当前生产路径时还直接写 `production_model_ref`，请求体没有 `sequence_contract` 或工件路径，也不调用统一校验（`backend-service/services/iterative_labeling/cumulative_training.py:685-716`）。对应 `POST .../modeling-paths/register-model` 直接暴露该行为，router 在 `main.py` 通过普通 `include_router()` 挂载，没有路由级认证依赖（`backend-service/api/iterative_labeling.py:2374-2424`，`backend-service/main.py:438`）。任何可访问后端的调用者都能在 seq 已是主线时替换生产引用；scheduler 即使随后拒绝不合格工件，生产指针也已被污染并导致预测停摆。

`mark_retrain_request()` — 输入重训状态、训练摘要和是否晋升，负责登记模型并可切换生产引用 — 的 `promote_to_production` 缺省为 true，完成分支对 seq 没有统一契约判断，直接更新生产引用和路径（`backend-service/services/iterative_labeling/cumulative_training.py:776-878`）。当前 API 给 seq 显式传 false，不能约束其他服务调用方；门控必须位于真正写生产状态的方法中。

## 随机批次重试会让未提交记录重复进入审核 [confirmed]

`_run_seq_annotation_prediction_cycle()` — 输入 PV 仓储和模型引用，落设备日预测、审核与游标 — 先过滤已有预测，再用随机 UUID 的新 `batch_id` 持久化批次和审核会话，随后循环调用 `insert_prediction_record()`（`backend-service/services/scheduler/tasks/pv_fault_tasks.py:927-1018`）。后者每次打开独立 session，逐条提交记录（`backend-service/services/db/repositories/pv_fault.py:169-196`）。

若第 k 条成功、第 k+1 条失败，第一次审核会话已经包含全部 `prepared_predictions`。重试只排除前 k 条，其余预测使用新 batch ID 创建第二个审核会话；审核 ID 只对同一 batch 幂等，不能跨随机 batch 合并（`backend-service/services/iterative_labeling/review_session.py:212-300`）。详情引用不再丢失，但未提交单元会同时存在于两个审核队列，人工裁决可能重复落账。

## 宽松 truthiness 让损坏或构造的 metadata 通过门控 [confirmed]

`final_sequence_contract_errors()` 对 `trained_full_day`、`grid_aligned`、`postprocessing.enabled` 与 `force_normal_outside_fault_window` 使用 `bool(value)`。非空字符串 `"false"` 因而为 true；其余字段合法、四个布尔字段均为字符串 `"false"` 的 payload 实测返回空错误列表。`normalize_postprocessing_contract()` 同样会把 `enabled="false"` 归一化为启用。

契约解析还直接对嵌套字段调用 `dict(...)`，并直接 `int(...)` 部分字段。实测 `training_config=1` 抛出 `TypeError: 'int' object is not iterable`；scheduler 工件加载只把 `FileNotFoundError`、`ValueError`、`RuntimeError` 归类为 `seq_annotation_model_invalid`，该异常会越过安全跳过分支，由外层任务记录 failed 后重抛（`backend-service/services/scheduler/tasks/pv_fault_tasks.py:764-799`）。
