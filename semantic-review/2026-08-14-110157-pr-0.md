## High-level view

五项历史问题均已闭合。`register_path_model()` — 输入建模路径键和模型引用、登记候选路径模型 — 现在拒绝 seq；`mark_retrain_request()` — 输入重训完成状态和训练摘要、负责登记及可选生产晋升 — 在 seq 晋升时执行统一契约。`final_sequence_contract_errors()` — 输入工件 metadata/序列契约并返回差异列表 — 严格检查 JSON boolean，并把非对象嵌套字段转成差异；scheduler 会安全跳过无效工件。

稳定 batch ID、批量原子写和同 batch 审核恢复只在输入完全不变时自洽。批次 ID 只包含模型引用和设备日单元，重试会重新计算并覆盖批次文件，而审核服务发现同 ID 会直接返回旧会话；晚到测量后，三处持久化事实会分叉。

legacy_day 没有失去显式生产切换能力，但写控制面未认证。普通登记不再直接覆盖生产引用，不过任意可达客户端仍可先登记 legacy 引用，再调用路径设置把它写成生产引用。

raw/postprocessed、处理后类别置信度和 segments 在 Predictor 主链保持一致；生产准入布尔也保持严格。scheduler 批次审计与 API overlay 仍使用 Python truthiness，损坏批次中的 `"false"` 会显示为 true。目标链路未发现绝对路径持久化或未使用 import，但文件级 AI 标记内仍嵌套局部标记。

## 稳定批次恢复会在输入变化后撕裂三份事实 [confirmed]

`_seq_prediction_batch_id()` — 输入模型引用和本轮设备日预测，输出稳定批次 ID — 只哈希 `model_ref` — 模型引用和 `(site_id, device_id, branch_id, time_window)` — 站点/设备/支路/时间窗单元，不包含源数据指纹、逐点预测或置信度（`backend-service/services/scheduler/tasks/pv_fault_tasks.py:689-714`）。失败重试会重新读取设备日、重新预测，并由 `_write_prediction_batch()` 覆盖同名 JSON（同文件 `717-764`）。

若第一次执行已创建审核会话、但在设备游标提交前失败，晚到测量可改变第二次预测而不改变 batch ID。数据库已有记录因 batch ID 相同进入恢复分支（同文件 `974-992`）；批次文件被覆盖，但 `ReviewSessionService.create_session()` — 输入预测批次和审核单元，创建或恢复审核队列 — 对已有 ID 直接返回旧会话，不核对或更新单元（`backend-service/services/iterative_labeling/review_session.py:202-225`）。数据库行保留第一次摘要和 segments，批次文件变成第二次详情，审核会话仍保留第一次标签/置信度。

恢复协议应把 prepared 批次视为不可变事实：重试优先加载原批次并补齐数据库、审核和游标。若改用内容哈希，还必须定义已有数据库业务键如何迁移；仅扩大 hash 无法让同设备日的新批次通过现有去重。

## legacy 显式切换仍在，但生产写接口没有认证边界 [confirmed]

`register_path_model()` 已禁止 `path_key` — 建模路径键为 `seq_annotation`，且 legacy 登记不再直接修改生产引用（`backend-service/services/iterative_labeling/cumulative_training.py:693-731`）。`set_modeling_paths()` — 输入 `production_path` — 生产主路径和 fallback，更新生产路径及对应模型引用 — 仍允许把已登记 legacy 模型显式设为生产，即使目标就是当前路径（同文件 `644-692`）。

router 没有全局 `Depends`，`PUT /api/iterative-labeling/cumulative-training/modeling-paths` 与 `POST /api/iterative-labeling/cumulative-training/modeling-paths/register-model` 也没有端点级认证（`backend-service/api/iterative_labeling.py:74,2398-2422`；`backend-service/main.py:438`）。实测先登记 `model_ref` — 模型引用为 `attacker-model`，再设置 `production_path="legacy_day"`，会得到 `production_model_ref="attacker-model"`。应为生产登记/切换增加运维权限与审计主体；seq 特有旁路虽然关闭，整个生产控制面仍可被任意可达客户端修改。

## 严格布尔没有污染生产门控，但审计回显仍 fail-open [confirmed]

Trainer 构造后处理契约时只接受 bool；Predictor 加载 `trained_full_day` — 是否全天训练和后处理契约时严格校验；API 重训把原始布尔交给生产契约。字符串布尔和 malformed nested object 已不能绕过生产准入。

`_normalize_predictions()` 仍用 `bool(detail.get("trained_full_day"))` 写批次详情（`backend-service/services/scheduler/tasks/pv_fault_tasks.py:655`），审核时序 API 又用同样转换构造 overlay（`backend-service/api/iterative_labeling.py:1623`）。损坏或手工修改批次里的 `"false"` 会被持久化/展示为 true，削弱审计可信度；这里应拒绝非 boolean，而不是再次使用 truthiness。
