## 已提交批次只能在重试单元集合完全相同时恢复 [confirmed]

`_run_seq_annotation_prediction_cycle()` — 输入 PV 仓储与生产模型引用，负责设备日推理、批次、数据库、审核和游标 — 先用新 `predictions` 计算 batch ID，再按设备、业务日和 `sample_id` — 预测样本键查询数据库。只有记录内旧 batch ID 等于本次新算 ID，才进入恢复分支（`backend-service/services/scheduler/tasks/pv_fault_tasks.py:1031-1069`）。该分支确实用首次 batch 的预测、来源路径和游标时间覆盖新推理值（同文件 `726-766, 1060-1149`）。

第一次批次 A 若含 `{d1, d2}`，数据库整批提交后在审核创建前失败，重试因晚到数据得到 `{d1, d2, d3}`，新 ID 变为 B。查询 d1/d2 时能读到 A，但代码只比较 A 是否等于 B，不收集 A；随后只为新单元 d3 写 B 和审核，A 未被加载。若新集合是旧集合子集，则全部命中不同 batch ID 后走 `all_duplicate`，同样不恢复 A。

恢复真源应是已提交记录里的旧 batch 引用，而不是第二次推理的完整单元集合。当前测试只验证 `_load_seq_recovery_batch()` 返回三类不可变字段，没有覆盖集合增减后的编排分支。
